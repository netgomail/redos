## `/usb-policy`: блокировать до авторизации, а не после (политика версии 6)

### Контекст

Сейчас (политика версии 5, `src/features/deviceControl.ts`) USB-устройство
сначала **авторизуется ядром**, к нему привязываются драйверы, и только потом
udev-правило `/etc/udev/rules.d/99-block-usb.rules` вызывает
`/usr/local/sbin/redos-block-usb.sh`, который пишет `0` в
`/sys/bus/usb/devices/<порт>/authorized`.

Между подключением и блокировкой проходят доли секунды. Для флешки этого мало,
но BadUSB-устройство, объявившее себя клавиатурой, в это окно успевает
«напечатать» команды. Правило и скрипт написаны корректно (сверено с `udev(7)`
systemd v252, `systemd-udevd.service` и `Documentation/usb/authorization.rst`
ядра) — окно заложено в саму схему.

Документация ядра закрывает окно так:

```
echo 0 > /sys/bus/usb/devices/usbX/authorized_default   # новые устройства не авторизуются
# udev-правило → скрипт пишет 1 только разрешённым
```

Так работает USBGuard. Риск: если скрипт не отработает, **новая клавиатура и
мышь не заработают**. Поэтому сначала эксперимент руками, потом код, и только с
доступом к машине по SSH.

### Выбранная схема (гибрид — не трогает загрузку)

- `authorized_default=0` ставится **udev-правилом на корневых хабах** (`usb1`,
  `usb2`, …), а **не** параметром ядра `usbcore.authorized_default=0`.
  Параметр ядра действует уже в initramfs — там нашего правила нет, и
  клавиатура не авторизуется при вводе пароля LUKS. Правило udev срабатывает
  только в основной системе.
- Устройства, подключённые **до загрузки**, ядро авторизует раньше, чем
  сработает правило хаба. Их по-прежнему гасит текущий путь (событие
  `usb_interface` → скрипт → `authorized=0`). Этот путь **остаётся** как второй
  рубеж.
- Устройства, подключённые **после загрузки**, появляются с `authorized=0`.
  Интерфейсов в sysfs у них нет — классы читаются из бинарного файла
  `descriptors` устройства. Скрипт решает по ним и пишет `1` только
  разрешённым.
- Рубеж по блочному узлу (`SUBSYSTEM=="block" … SUBSYSTEMS=="usb"`) остаётся
  без изменений.

### Шаг 0. Собрать окружение (записать вывод в отчёт)

```bash
cat /etc/redos-release; uname -r; systemctl --version | head -1
getenforce 2>/dev/null || echo "SELinux нет"
for h in /sys/bus/usb/devices/usb*; do echo "$h $(cat $h/authorized_default)"; done
lsusb -t
cat /etc/redos/device-control.conf 2>/dev/null | head -12   # текущая политика, версия
```

Ожидаемо: `authorized_default` = `1` на всех хабах. Если там уже `0` или `2`,
значит, кто-то настроил блокировку (USBGuard, параметр ядра) — остановиться и
сообщить.

### Шаг 1. Эксперимент руками (до любых правок кода)

Выполнять под root, **с открытой SSH-сессией** с другой машины или со второй
клавиатурой на другой шине. Нужна флешка и, по возможности, USB-клавиатура.

1. Найти шину со свободным портом (`lsusb -t`), например `usb2`.
2. Закрыть шину для новых устройств:
   ```bash
   echo 0 > /sys/bus/usb/devices/usb2/authorized_default
   ```
3. Вставить флешку в порт этой шины. Найти её порт (`dmesg | tail`,
   `ls /sys/bus/usb/devices/`), например `2-4`, и записать:
   ```bash
   d=/sys/bus/usb/devices/2-4
   cat $d/authorized                          # ожидаем 0
   ls $d                                      # есть ли каталоги интерфейсов 2-4:1.0 (ожидаем НЕТ)
   cat $d/idVendor $d/idProduct               # читаются?
   cat $d/serial $d/product $d/manufacturer   # КРИТИЧНО: читается ли serial у неавторизованного
   od -An -tx1 -v $d/descriptors | head       # есть ли дескрипторы конфигурации
   ls /dev/sd*                                # блочного узла быть не должно
   ```
   **Главный вопрос эксперимента — `serial`.** Список доверенных устройств
   (`TRUSTED=` в политике) хранит `vid:pid:serial`. Если у неавторизованного
   устройства serial пустой или `n/a (unauthorized)`, доверенные устройства
   придётся сначала авторизовать и потом сверять, либо хранить ключ иначе.
   Записать фактическое значение.
4. Проверить, что авторизация поднимает устройство:
   ```bash
   echo 1 > $d/authorized; sleep 1; ls $d; ls /dev/sd*   # интерфейсы и /dev/sdX появились
   ```
5. Повторить шаги 3–4 с USB-клавиатурой: пока `authorized=0`, она не печатает,
   после `1` — печатает.
6. **Вернуть шину:** `echo 1 > /sys/bus/usb/devices/usb2/authorized_default`.

Если что-то пошло не так (например, `serial` не читается, `descriptors` пуст),
**не переходить к шагу 2** — записать результаты сюда и обсудить схему.

### Шаг 2. Реализация (файл `src/features/deviceControl.ts`)

1. **`POLICY_VERSION = 6`**, дописать историю версий в комментарий над
   константой. В `USBPolicyScreen.tsx` текст про устаревшую политику
   (`st.outdated`) дополнить.
2. **`generateRules()`** — добавить сразу **после** строки
   `ACTION!="add", GOTO="redos_dc_end"` (правила должны видеть только add),
   до рубежа по блочному узлу:
   ```
   # Корневой хаб: новые устройства на нём не авторизуются, решает скрипт.
   SUBSYSTEM=="usb", ENV{DEVTYPE}=="usb_device", KERNEL=="usb[0-9]*", ATTR{authorized_default}="0", GOTO="redos_dc_end"
   # Новое устройство на закрытой шине: решение по дескрипторам.
   SUBSYSTEM=="usb", ENV{DEVTYPE}=="usb_device", ATTR{authorized}=="0", RUN+="/usr/local/sbin/redos-block-usb.sh --device $devpath", GOTO="redos_dc_end"
   ```
   Существующие строки (блочный узел, `usb_interface`) не менять. Присваивание
   `ATTR{…}="0"` пишет в sysfs — `udev(7)`: «ATTR{key} — The value that should
   be written to a sysfs attribute of the event device».
3. **`BLOCK_SCRIPT_BODY`** — третий режим `--device`:
   - `dev="/sys$2"`; если `authorized` уже `1` — выйти.
   - Доверенные (`TRUSTED`) — как сейчас, по `vid:pid:serial` (с учётом
     результата шага 1).
   - Классы интерфейсов — из `$dev/descriptors` через `od -An -tx1 -v`: идти по
     записям (байт 0 — длина, байт 1 — тип), брать тип `04` (интерфейс) с
     `bAlternateSetting` (байт 3) = `00`, класс/подкласс/протокол — байты 5/6/7;
     остановиться на второй конфигурации (тип `02`). Это повтор
     `declaredInterfaces()` из того же файла (строки ~655–688), нормализацию
     SCSI (подкласс `06`, протокол `50`/`62` → класс `08`) — как в режиме
     интерфейса.
   - Дальше та же логика решения (опасные комбинации, токены, классы), но
     вместо `block()` — ничего не делать (устройство и так не авторизовано), а
     при разрешении — `printf 1 > "$dev/authorized"`.
   - Хабы (класс устройства `09`) разрешать всегда: иначе всё, что за хабом,
     останется неавторизованным. Категория «хабы» и так в `LOCKED_CATEGORIES`.
   - Вынести общий код решения в функцию, чтобы режимы не расходились.
4. **`removePolicy()`** — после удаления файлов вернуть
   `authorized_default=1` на всех `usb*` и авторизовать неавторизованные
   (`authorizeAll()` уже есть). Без этого после снятия политики новые
   устройства не будут работать до перезагрузки.
5. **`applyPolicy()`** — после `udevadm trigger` убедиться, что на всех
   корневых хабах `authorized_default` = `0`; если правило не выставило —
   выставить напрямую и сообщить в шаге. Сетка безопасности по устройствам
   ввода (шаг 4 функции) остаётся.
6. **`readStatus()` / экран** — показать строку «новые устройства: блокируются
   до проверки (authorized_default=0)» или предупреждение, если хабы открыты.

### Шаг 3. Тесты (`src/features/deviceControl.test.ts`)

Там уже есть стенд `decide()` — фальшивое дерево sysfs во временном каталоге,
через который гоняется настоящий скрипт. Добавить:

- режим `--device`: устройство с `authorized=0` и файлом `descriptors`
  (собрать байты: дескриптор устройства 18 байт, конфигурации 9 байт,
  интерфейсы по 9 байт) → разрешённый класс даёт `authorized=1`, запрещённый
  оставляет `0`;
- флешка `08:06:50` при выключенных «Накопителях» → остаётся `0`;
- клавиатура `03:01:01` → `1` (ввод всегда разрешён);
- BadUSB `{08, 03}` → остаётся `0`;
- вендорский `ff:06:50` при выключенных накопителях → `0` (нормализация SCSI);
- хаб `09` → `1`;
- доверенное устройство по `vid:pid:serial` → `1`;
- `generateRules()` содержит правило хаба с `ATTR{authorized_default}="0"` и
  правило `--device`;
- `appliedVersion(generatePolicy(...)) === 6`.

`bun test` и `bunx tsc --noEmit -p .` — зелёные.

### Шаг 4. Проверка на машине

Собрать (`bun run build`), скопировать `dist/redos-linux` на машину, **SSH
открыт**. Применить политику через `/usb-policy` (накопители выключены), затем:

| Действие | Ожидаемо |
|---|---|
| `cat /sys/bus/usb/devices/usb*/authorized_default` | везде `0` |
| Вставить флешку | `authorized=0`, `/dev/sdX` **не появлялся** ни на миг (`udevadm monitor --udev --subsystem-match=block` — событий нет) |
| Вставить USB-клавиатуру | печатает (авторизована скриптом) |
| Вставить мышь, принтер, смарт-карту/токен | работают |
| Переподключить USB-хаб с клавиатурой за ним | хаб и клавиатура работают |
| Доверенная флешка из исключений | монтируется |
| Перезагрузка | клавиатура работает на экране LUKS/входа; после загрузки — таблица выше снова верна |
| «Снять политику» в `/usb-policy` | `authorized_default` = `1`, новая флешка монтируется |

Дополнительно:
```bash
udevadm verify /etc/udev/rules.d/99-block-usb.rules   # systemd ≥ 253
journalctl -u systemd-udevd -b | grep -i redos        # ошибок запуска скрипта нет
ausearch -m avc -ts recent | grep redos                # SELinux ничего не запретил
```

### Аварийный откат (если пропала клавиатура)

По SSH:
```bash
for h in /sys/bus/usb/devices/usb*; do echo 1 > $h/authorized_default; done
for d in /sys/bus/usb/devices/*/authorized; do echo 1 > $d; done
mv /etc/udev/rules.d/99-block-usb.rules /root/99-block-usb.rules.off
udevadm control --reload-rules
```
Без SSH: перезагрузка — устройства, подключённые при загрузке, авторизуются
ядром до срабатывания правила, клавиатура на месте; затем выполнить то же
локально. Если и это не помогло — в GRUB добавить к строке ядра
`systemd.unit=rescue.target` и удалить правило.
