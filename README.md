# РедОС

> Консольная утилита для специалиста по защите информации — парольная и USB-политики, печать и сканирование, инвентаризация Linux-систем. Заточена под РедОС 7/8 (RHEL-based).

---

## Установка

```bash
curl -fsSL https://raw.githubusercontent.com/netgomail/redos/master/install.sh | bash
```

Установщик автоматически скачивает последнюю версию из GitHub Releases и добавляет `redos` в PATH.

---

## Обновление

```bash
redos update
```

---

## Запуск из исходников

Требуется [Bun](https://bun.sh) ≥ 1.4 (нужен `Bun.Terminal`).

```bash
bun install
bun start
```

## Команды

### Служебные

| Команда | Описание |
|---|---|
| `/help` | Список всех команд |
| `/clear` | Очистить историю |
| `/exit` / `/quit` | Завершить работу |

### Безопасность

| Команда | Описание |
|---|---|
| `/passwd-policy` | Парольная политика — сложность пароля, срок смены, принудительная смена при входе. |
| `/usb-policy` | Контроль устройств на USBGuard — блокировка групп USB-устройств на уровне ядра. |

### Оборудование

| Команда | Описание |
|---|---|
| `/printer` | Печать и сканирование — диагностика и лечение очереди CUPS, режим «только один МФУ». |

### Инвентаризация

| Команда | Описание |
|---|---|
| `/inventory [файл.txt]` | Инвентаризация системы: ОС, железо, диски, пользователи, сеть, открытые порты, сервисы. |

Все команды кроме `/inventory` требуют root — в графической сессии права
запрашиваются через polkit, в терминале нужен `sudo redos`. **Только Linux.**

## `/passwd-policy` — детали

Полноэкранный режим с тремя действиями:

- **Применить пресет «Базовая»** — `minlen=8`, `minclass=3`, `PASS_MAX_DAYS=90`. Опционально применяет `chage -M -m -W` к выбранным пользователям.
- **Применить пресет «Усиленная»** — `minlen=12`, `minclass=4`, `PASS_MAX_DAYS=60`. То же самое для существующих пользователей.
- **Форсировать смену пароля при входе** — `chage -d 0` для выбранных пользователей; при ближайшем входе система потребует новый пароль.

Куда пишутся настройки:

| Файл | Что |
|---|---|
| `/etc/security/pwquality.conf.d/50-redos.conf` | Параметры сложности (drop-in, основной `pwquality.conf` не трогается) |
| `/etc/login.defs` | `PASS_MAX_DAYS`, `PASS_MIN_DAYS`, `PASS_WARN_AGE`. Перед записью создаётся `*.bak.YYYYMMDD-HHMMSS` |
| `/etc/shadow` (через `chage`) | Сроки и флаг «сменить при входе» для существующих пользователей |

PAM-стек `/etc/pam.d/system-auth` / `password-auth` **не редактируется** — он управляется `authselect`. `pam_pwquality` уже подключён в нём по умолчанию и подхватывает drop-in.

## `/usb-policy` — контроль устройств

Блокировка построена на [USBGuard](https://usbguard.github.io) — он запрещает
устройства **на уровне ядра**: неавторизованная флешка не конфигурируется, узла
`/dev/sdX` не появляется, и смонтировать её не может даже root. Если пакета нет,
утилита ставит его из штатного репозитория РЕД ОС.

> Прежний механизм на udev-подсказке `UDISKS_IGNORE` не блокировал: он гасил
> только автомонтирование. Устройство оставалось авторизованным, а polkit по
> умолчанию разрешает активному локальному пользователю монтировать без пароля —
> через «Диски» или `udisksctl mount`.

### Модель

Администратор **блокирует группу** устройств и **разрешает отдельные**.

| | |
|---|---|
| Блокируются категориями | накопители, веб-камеры, звук, сеть и модемы, Bluetooth |
| Разрешены всегда | хабы, клавиатуры и мыши, принтеры, сканеры, смарт-карты, криптотокены |
| Разрешаются поимённо | любое устройство из списка исключений |

Политика — белый список, как рекомендуют разработчики USBGuard: разрешено только
явно разрешённое. Обратная модель в их документации названа неверной, и не зря —
встроенный картридер Realtek объявляет класс `ff:06:50`, а не `08`, и из чёрного
списка по классу накопителей просто выпал бы.

### Что попадает в правила

```
reject with-interface all-of { 08:*:* 03:00:* }        # BadUSB: накопитель + клавиатура
allow id 0a89:*                                        # криптотокены Актив
allow with-interface match-all { 09:*:* 03:*:* ... }   # разрешённые категории
allow id 0951:16aa serial "..." hash "..."             # исключение
# всё остальное блокируется неявно: ImplicitPolicyTarget=block
```

Заблокированных устройств в файле нет вообще — блокирует отсутствие разрешения.
`match-all` вместо `one-of` принципиален: устройство проходит, только если **все**
его интерфейсы в разрешённом наборе, иначе комбо «флешка + клавиатура» прошло бы
по одному лишь HID.

### Криптотокены

Разрешены всегда и опознаются по производителю, а не по классу: `Rutoken lite HID`
и `Rutoken ECP HID` объявляют себя устройствами ввода, `Rutoken Mass Storage` —
накопителем, `Rutoken S` — вендорским классом. Запрет накопителей иначе отрубил бы
вход по токену и подпись.

## `/printer` — печать и сканирование

Две задачи из практики с HP LaserJet MFP M426fdn на РедОС 8.

### «Принтер отвалился»

При разовой ошибке бэкенда CUPS по умолчанию (`error-policy=stop-printer`)
останавливает очередь и **сам её обратно не включает** — печать пропадает до
ручного вмешательства. Особенно часто это даёт бэкенд hplip (`hp:/net/...`,
`open device failed stat=12`), когда МФУ уснул или занят. В журнале видно
`Printer stopped due to backend errors`.

**Диагностика очереди** показывает состояние, `error-policy`, ping до аппарата,
порты 631/9100, ответ по eSCL и последние записи об ошибках из журнала cups.

**Починить очередь** делает то, что лечит проблему насовсем:

| Шаг | Зачем |
|---|---|
| `lpadmin -v ipp://IP/ipp/print -m everywhere` | уход с ненадёжного hplip на драйверless IPP Everywhere |
| `lpadmin -o printer-error-policy=retry-job` | CUPS больше не останавливает очередь из-за разовой ошибки |
| `cupsenable` + `cupsaccept` | включить очередь и приём заданий |
| `cancel -a` | снять застрявшие задания, они мешают следующим |

### «Только один МФУ»

Если в сети несколько одинаковых аппаратов, через mDNS они все лезут в списки
печати и сканирования — на каждый ещё и по два сканера (airscan и hpaio).
Пользователь выбирает не тот и «принтер не печатает».

Мастер ищет аппараты по mDNS и через CUPS, опрашивает их по eSCL (кто ответил —
настоящий МФУ со сканером), либо принимает IP вручную. После подтверждения:

| Что делается | Результат |
|---|---|
| очередь на `ipp://IP/ipp/print` + `retry-job` | одна рабочая очередь |
| остальные очереди удаляются | в списке печати ровно один принтер |
| `/etc/sane.d/dll.conf` → только `airscan` | лишние бэкенды сканирования отключены |
| `/etc/sane.d/dll.d/hpaio` → `.disabled` | hpaio дублировал тот же аппарат |
| `/etc/sane.d/airscan.conf` → `discovery = disable` + устройство по IP | автопоиск не подтягивает чужие сканеры |
| `systemctl mask avahi-daemon` (можно отключить клавишей `A`) | mDNS больше не показывает чужие аппараты |

Перед изменениями создаётся бэкап `/root/redos-mfp-backup-<дата>/` со скриптом
`rollback.sh`. Удалённые очереди печати он не восстанавливает — их заводят заново.

> Экран подтверждения перечисляет все необратимые изменения до их применения.

├── install.sh               — установщик Linux x86_64
